## What became a shim

Every module under `src/skos/autopilot/` and `src/skos/autopilot/adapters/`
now has the form:

```python
"""Shim: re-exports skharness.autocode.<mod> ..."""
from skharness.autocode.<mod> import *  # noqa: F401,F403
from skharness.autocode.<mod> import <private names>  # only where needed
```

Top-level (15): `ci, claude_code, config, digest, engineering, executor,
harness, journal, orchestrator, remediation, resolver, sandbox, sandbox_proxy,
stubs, types`.

Adapters (5): `base, claude_code, codex, opencode, pi`.

Package `__init__.py` files (2): `autopilot/__init__.py` kept as a docstring
(unchanged behavior, now notes shim status). `autopilot/adapters/__init__.py`
became `from skharness.autocode.adapters import *` + `__all__`; importing
`skharness.autocode.adapters` runs ITS body, which calls `register_harness(...)`
for each adapter into the single shared `HARNESSES` dict
(`skharness.autocode.harness.HARNESSES`, a mutable object, same identity
regardless of which package name imports it) exactly once (Python caches
`skharness.autocode.adapters` in `sys.modules`). So registration happens once,
sourced from skharness, whichever import path (skos shim or skharness direct)
triggers it first. `harness.build_harness()` itself also lazily
`import skharness.autocode.adapters` internally (moved verbatim in Phase A),
so registration is reliable even if nothing ever imports the skos adapters
shim at all.

No `__all__` is defined in any of the moved modules (except `adapters/`), so
`import *` picks up every public (non-underscore) top-level name automatically.

## A real correctness issue found and fixed (not papered over)

The naive `from skharness.autocode.X import *` shim is transparent for
**external** callers (anything that does `skos.autopilot.X.symbol`, e.g.
`skos.cli`, since the caller's own attribute lookup goes through whichever
module object it holds a reference to). It is **not** transparent for a test
that `mocker.patch`/`monkeypatch.setattr`es a name on the shim module,
expecting to intercept a call made **from inside** the original module's own
code: `EngineeringExecutor.run()` (and `orchestrator.run_once()`,
`orchestrator.run_cli()`, `engineering.revert()`, `digest.send_digest()`)
resolve names like `external_ci_verdict`, `journal`, `run_once`,
`build_harness`, `_load_board`, `rebuild_manifest` against **their own**
module's `__globals__` (i.e. `skharness.autocode.<mod>.__dict__`), which is a
different dict object from the shim's `__dict__` that `mocker.patch("skos.
autopilot.<mod>.<name>", ...)` mutates. Patching the shim's copy is a silent
no-op for those internal self-calls; the real function runs instead.

This is standard Python/`unittest.mock` semantics ("patch where it's used"),
not a bug in the shim design, but it broke 12 of the 286 selected skos
autopilot tests once the shim went in, because those tests' patch-target
strings named the shim path. I fixed each by retargeting the specific
`mocker.patch`/`monkeypatch.setattr` calls that patch an **internally
self-called** name to `skharness.autocode.<mod>.<name>` (the module the code
actually runs in), leaving every test's own `from skos.autopilot import X`
**import** statement unchanged (still proving the shim import path resolves).
No assertion, fixture behavior, or test intent changed; every fix is a
patch-target string only, with an explanatory comment. No skharness file was
touched.

## Note: skharness.autocode is not a strict byte-identical Phase A snapshot

Diffing `skos/src/skos/autopilot/` against
`skharness/src/skharness/autocode/` before this change showed skharness's
copy has moved ahead of a pure Phase A rename: it already carries the
companion "hardcore-vs-simple toggle" spec's `QualityMode` enum, a new
`direct.py` module, and `GateResult.mode`/`RepoSpec.min_quality` fields. These
are additive-only (new enum, new fields with safe defaults, a
back-compat-preserving `getattr(result, "mode", "gated")` guard in
`EngineeringExecutor.finalize`) and did not affect skos's behavior or its
test suite (skos never constructs those fields, so every existing call site
gets the same defaults it always did). Flagging for visibility since the task
description assumed a byte-identical Phase A copy; not a blocker for Phase B,
and not something I touched or need to touch (skharness was not modified).
